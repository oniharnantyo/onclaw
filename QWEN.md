## Project Overview

**onclaw** is an on-device, multi-agent AI coding assistant CLI designed for
**low-resource single-board computers (~2 GB RAM, 8 GB storage)** — Raspberry Pi /
Orange Pi class. Every design choice favors a tiny footprint: a single
**statically-linked binary** (`CGO_ENABLED=0`, stripped), a **pure-Go SQLite**
(`modernc.org/sqlite`, no libc, so it cross-compiles to ARM cleanly), and
conservative defaults. The agent runtime is built on **cloudwego/eino** (ADK),
wrapped by onclaw-specific middlewares.

Two surfaces ship from the same binary:
- **CLI** (`urfave/cli/v3`) — `init`, `provider`, `agent`, `skill`, `mcp`, `hooks`, `memory`, `chat`, `run`, `config`, `serve`.
- **Web console + JSON API** (`onclaw serve`) — React 19 SPA served from
  embedded assets, talking to a `net/http` REST API behind password auth.

## Architecture

`main.go` is trivial: it imports the browser tool package for side-effect
registration, then calls `clicmd.New().Run(...)`. All wiring lives in
`internal/cli`.

```
main.go
└── internal/cli            # Command tree (urfave/cli v3). Assembly root.
    └── context.go          # getProviderManager(): opens SQLite, decrypts DEK,
                            #   assembles llm.Service + stores. Read FIRST.
internal/llm                # Service facade: ProfileStore + SecretStore +
                            #   KeyManager + adapter.Registry + AgentStore.
                            #   Caches profiles + decrypted keys behind an
                            #   atomic reloadPending flag (hot-reload).
internal/agent              # AssembleAgent(): builds an Eino TypedChatModelAgent
                            #   with onclaw middlewares. Run() → EventIterator.
    ├── tools              # Builtin tools: filesystem (via Eino middleware),
    │                       #   memory, kg_search, web, browser. Registry + config.
    ├── middlewares        # input-safety, summarization, history, fs-toggle,
    │                       #   fs-error, memory, skill, hooks middleware.
    └── templates          # Persona / AGENTS.md loading.
internal/store              # interfaces (store.go) + DTOs (types.go) + sqlite/.
internal/secrets            # AES-256-GCM, DEK/KEK, keyfile/Argon2id.
internal/memory             # core, episodic, knowledge-graph, embedding,
                            #   extraction, dreamer, security scan, staged writes.
internal/hooks              # Dispatcher + events (SessionStart, Stop, …).
internal/mcp                # Manager + client.
internal/skill              # Skill installer.
internal/api                # net/http REST API + embedded static web assets.
    ├── handler, service, auth, httpx
    └── assets              # Built web UI (generated by `make ui`).
internal/config             # Viper layered config (ONCLAW_* env).
internal/{logging,observability,modelmeta,render,shellpolicy,browser,workspace,web,version}
```

### Assembly root — `internal/cli/context.go`

`getProviderManager(c)` is the spine: resolve DB path → `sqlite.Open` →
`sqlite.Migrate` → on first run generate a DEK and wrap it under a keyfile
(`SwitchToKeyfile`), else decrypt the wrapped DEK → build `ProfileStore`,
`SecretStore`, `AgentStore`, `KeyManager`, an `adapter.Registry` seeded with
`adapter.DefaultAdapters`, and finally `llm.NewService(...)`. The same function
also returns the `MCPServerStore` and `*sql.DB`.

### LLM service

`llm.Service` is a thin facade. `BuildAgent(ctx, name)` resolves the agent's
effective provider profile (merging agent-level `reasoning_effort` /
`reasoning_budget_tokens` into provider settings), resolves the API key
(`ONCLAW_PROVIDER_<NAME>_API_KEY` env > DB, keyless providers like Ollama
tolerate a missing key), and dispatches to the registered adapter, which returns
an Eino `model.AgenticModel`. Profiles + decrypted keys are cached in memory and
invalidated via the `reloadPending` atomic + `fsnotify` watcher + SIGHUP.

### Agent

`agent.AssembleAgent(...)` builds a `ChatModelAgent` with this middleware chain
(in order): `inputSafety` → `summarization` (Eino, triggers at 80% of context
window or 200 messages) → `history` → `filesystem` (Eino, injects ls/read/write/
edit/glob/grep/execute) → `fsToggle` (honors `tool_registry` enable flag) →
`fsError` (recoverable observations) → `memory` (when enabled) → `skill` →
`hooks`. Tools are built from `tools.Builtin(scope, enabledChecker)` plus any
MCP tools. `Run()` returns an `EventIterator` for streaming. `onclaw run` is the
CLI entry; the web console assembles through `api/service.ResolveAndAssembleFunc`.

### Config

`internal/config` (Viper): priority `defaults < .env file < ONCLAW_* env < CLI
flags`. `.env` is searched in `.`, `~/.onclaw`, `/etc/onclaw`. `onclaw config
show` prints the merged result. Env keys are `ONCLAW_`-prefixed
(`log_level` → `ONCLAW_LOG_LEVEL`). Memory-relevant keys:
`max_context_tokens`, `concurrency`, `tools.shell.policy/{allow,deny}list`,
`memory.*` (embedding provider/model, char_limit, write_approval, fts/vector
weights, dream_threshold, episodic_ttl_days, kg_enabled, kg_traversal_depth).

### Store layout (STRICT)

- `internal/store/types.go` — DTOs only.
- `internal/store/store.go` — interfaces only (no implementations).
- `internal/store/sqlite/*.go` — concrete impls, **one file per entity**
  (`agent.go`, `conversation.go`, `profile.go`, `secret.go`, `kv.go`,
  `mcp_server.go`, `hooks.go`, `memory.go`, `episodic.go`, `knowledge_graph.go`,
  `skill.go`, `staged_writes.go`, `tool_registry.go`, `tool_group_config.go`),
  with `db.go` owning `Open` / `Migrate` / connection lifecycle.
- Never co-locate an interface with its implementation.

## Build, Run, Test

All builds produce a fully static binary (CGO disabled). **`make build` depends
on the web UI being built first** (`ui` target → `cd web && npm run build`), so
the embedded assets exist.

```bash
# Build (also builds the web UI into internal/api/assets)
make build                 # → bin/onclaw
make build-all             # cross-compile linux amd64 / arm64 / armv7

# Run
./bin/onclaw init          # interactive onboarding
./bin/onclaw serve --set-password   # set web console password (required once)
./bin/onclaw serve         # web console + JSON API (http://localhost:8080)
./bin/onclaw chat          # CLI chat
make run ARGS='version'    # build then run

# Quality
make test                  # go test ./...
make vet                   # go vet ./...
make lint                  # golangci-lint, falls back to go vet
make fmt                   # gofmt -s -w .

# Focused
go test ./internal/secrets/...
go test -run TestName ./internal/cli/...
```

**Web UI** (`web/`): `npm run dev` (Vite dev server), `npm run build`,
`npm run test` (`tsx src/runAllTests.ts`), `npm run lint` (`oxlint`).

**Release**: `make release` (GoReleaser snapshot), `.goreleaser.yaml`.

## Web UI

Frontend lives in `web/`. The **design system is the source of truth for all UI
work**: `web/design-system/onclaw/MASTER.md` (dark palette — `#0F172A` bg,
`#22C55E` accent; Inter font; spacing/shadow tokens; component specs).
Page-specific overrides live in `web/design-system/onclaw/pages/` and win over
the Master.

### Config forms: structured fields, never raw JSON

Every configuration dialog MUST render **one form field per config property**
(select / text / number / checkbox, each with a label, tooltip, inline
validation), derived from the config's JSON schema or DTO. Never expose editable
config as a single raw-JSON `<textarea>`. A read-only JSON `<pre>` preview is fine
for *displaying* stored config, never for editing it. Free-text/code whose
content is genuinely unstructured (hook scripts, agent system prompts) stays as
`<textarea>`s — those are values, not structured config.

### Routing (`react-router-dom` v7)

- `/chat` — live chat
- `/agents`, `/agents/new`, `/agents/:name` (tabbed: Overview, Hooks, Skills, Memory, MCP, Tools, Persona)
- `/memory`, `/mcp`, `/tools`, `/hooks`, `/skills`, `/providers` — aggregate top-level pages across all scopes

## Conventions

**Go style** — `.claude/rules/coding-style.md` is authoritative:
- `gofmt` (tabs), no parentheses in control structures, `MixedCaps` exported names.
- `context.Context` **first** parameter on all public functions; unused-by-
  convention ctx params are named `_`.
- Error wrapping with `fmt.Errorf` + `%w` (required for `errors.Is`/`errors.As`);
  return early, success path runs down the page.
- Many small files; contract / types (`types.go`) / implementation separated.

**Testing** — `internal/...` tests are **black-box** (`<pkg>_test` packages with
qualification) unless a private algorithm needs direct testing (then re-export
via `export_test.go`). Every `internal/...` package targets **≥ 70% statement
coverage** (exemptions recorded in the `testing-conventions` OpenSpec spec).
Test files match implementation file names (`profile.go` → `profile_test.go`);
shared helpers in `testutil.go`.

**Security** — never log or return decrypted secrets in the clear;
`internal/logging/` redacts known credential fields. Web console password is
`bcrypt`-hashed into the KV store (`web_password_hash`); `serve` refuses to start
without it.

**Feature planning** — OpenSpec drives planned changes. Specs under
`openspec/specs/` (e.g. `agent-core`, `agent-memory`, `agent-tools`, `chat-ui`,
`web-ui`, `testing-conventions`, `providers`, `model-discovery`). Check
`openspec/changes/` before designing non-trivial features; archive completed
work under `openspec/changes/archive/`.

**Hot-reload** — `onclaw provider …` edits write a PID file and `SIGHUP` the
running process; an `fsnotify` watcher is the in-process fallback. Both set
`Service.reloadPending`, so the next request re-reads from SQLite.

|---|---|
