# Design — regenerate-enhances-prompts

## D1 — Enhance framing shares the document spec
The system prompt keeps its document-specification block (document shapes, voice rules, JSON output format) and gains two framings: the existing "generate three foundational documents" task line for fresh generation, and an enhance framing used when documents exist — the model receives the current documents inline and is instructed to strengthen them: preserve structure and established voice, fix weak sections, incorporate the current brief, never start over. `BuildGenerationMessages(agent, current, instruction)` takes the current documents (nil = fresh) and an optional client instruction; a non-empty instruction rides along as a `### Requested Changes` section in both modes — the old documents are never dropped in favor of the instruction. The message builder and the tool/schema contract (`submit_prompts` JSON with identity/soul/bootstrap keys) are unchanged.

## D2 — Backup-on-write, abort-on-backup-failure
`WritePromptDocuments` keeps its signature; the commit sequence gains a backup phase between staging and the renames: for each document that already exists on disk, copy its current content to `<name>.bak` via staged temp + rename (same atomic pattern as the documents). Backups run for all three documents before any commit rename; a backup failure removes staged files, leaves the originals untouched, and returns an error → the service marks the generation failed. First writes (fresh create) find no existing documents and back up nothing. One prior version per file; a newer regen overwrites the `.bak` with the then-current content.

## D3 — Regenerate reads, never trusts
`Generate` reads the agent's current documents from `agent.WorkspaceDir` before invoking the model; read errors degrade to fresh mode (nil current). At least one non-empty document switches the pipeline to enhance mode. The generate-before-persist invariants hold unchanged: files are written only after the model call succeeds, delete-in-flight no-ops and the directory re-verify stay as-is, and `s.fail` never touches files.

## D4 — Prompts tab, not an Identity-tab annex
The config modal's edit mode gains a Prompts tab between Capabilities and Memory. It hosts the status row, the failed banner, Regenerate, and a two-pane document view: file list on the left, selected-file preview on the right — IDENTITY.md and SOUL.md as editable textareas (PATCH identity/soul on Save changes — the PATCH contract is unchanged), BOOTSTRAP.md read-only (PATCH has no bootstrap field — out of scope here). The Identity tab reverts to pure identity fields. Regenerate first asks what should change: the change-request form's submission calls the regenerate endpoint with an optional `instruction` (empty allowed), and the modal stays open and refetches the agent detail instead of closing, so the user sees the enhanced documents land; the roster Retry flow is untouched (no instruction).
