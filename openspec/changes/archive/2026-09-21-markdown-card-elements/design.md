# markdown-card-elements — Design

## Context

The transcript already renders assistant text through react-markdown with a custom `components` override (`MarkdownBody` in `AgentMessage.tsx`, memoized per delta, lazy KaTeX for math); the generative-UI registry (`web/src/lib/generativeUi/`) dispatches on a `$type` envelope and mounts ChartCard/TimelineCard/PreviewCard, today fed by three echo tools (`ui.chart`/`ui.timeline`/`ui.preview`). The system prompt is composed per run by `DefaultInstructionComposer.Compose` (attended) and `trimmedUnattendedDocs` (scheduler/heartbeat), which read the L1 base prompt from the seeded per-agent file `readPromptFile(dir, "AGENTS.md")` — seeded write-once by `promptdocs.SeedWorkspace` from the embedded template, so template updates never reach existing workspaces (the "vintage" divergence design D11 routes around). The assistant-ui elements catalog distributes copy-in source via the shadcn registry (`@assistant-ui/...`); installed components style themselves with shadcn-standard token classes (`bg-background`, `text-foreground`, `border-border`). `web/` has Tailwind v4 via `@tailwindcss/vite` and no `components.json`. See proposal.md — Why.

## Goals / Non-Goals

- Goals: cards without tool calls; every agent carries the fence conventions; per-build L1 injection; contract-consistent styling with one aliasing seam; graceful degradation everywhere.
- Non-Goals: no provider-level structured output (constrains whole responses or needs tool calls — both rejected); no wire-format, storage, or assistant-ui runtime changes; no new per-agent config surface for toggling the cards doc; no server-side fence validation (validation is render-time; the model self-corrects only via prompt quality); channels/Telegram/WhatsApp transcripts inherit fence rendering via the same message renderer — no per-gateway work.

## Decisions

- **D1 — Markdown fences as the transport; echo tools deleted.** The model writes tagged fences in message text; the renderer mounts cards. Rejected alternatives: provider `response_format` (constrains whole replies, kills prose streaming, touches every text consumer); keeping tools alongside fences (two transports for one visual, schema cost without a validation benefit that survives — see D2); markdown-only conventions without validation (no per-shape checks → broken cards render as blank-looking frames rather than their source).
- **D2 — Render-time validation, fail-open.** The frontend validates each fence body against its shape (required fields, enums, absolute http(s) preview URLs, `recommendedId` ∈ options) and mounts only valid bodies; anything else degrades to the ordinary code block. This preserves the element's prop contract (the guarantee the Go tools used to provide) without a backend round trip. Trade-off accepted: the model no longer receives a validation error to self-correct — a bad fence just degrades silently.
- **D3 — Registry stays the single mount logic.** `generativeUi/registry.tsx` gains `renderSpecByType(type, props, ctx)`; the fence path and the retained `$type` tool-result path (legacy transcripts) call the same registered renderers. The coverage-guard test's `GENERATIVE_UI_TYPES` set grows with the new tags.
- **D4 — Catalog source via shadcn; tokens via one aliasing seam.** Elements install with `npx shadcn@latest add "@assistant-ui/elements-…"` (names: `elements-data-table`, `elements-number-ticker`, `elements-activity-graph` (pulls `heat-graph`), `elements-spec-sheet`, `elements-comparison-card`, `elements-job-progress`, `elements-score-breakdown`, `elements-flow-graph`, `elements-math-block`, `elements-diagram`, `mermaid-diagram`, `shiki-highlighter`; shared infra `elements-surfaces`/`elements-range` arrive as registry dependencies). A Tailwind v4 `@theme inline` block maps shadcn token names onto OnClaw contract tokens (`--color-background: var(--bg)`, `--color-foreground: var(--fg)`, `--color-border: var(--border-line)`, `--color-popover: var(--surface)`, `--color-accent: var(--accent)`), so installed cards inherit the contract; `elements-surfaces` (the shared recipe file) gets a per-item restyle review rather than 12 per-card rewrites. `lucide-react` (wanted by comparison/job-progress) may be swapped for the in-house `Icon` at implementation if the dependency surface should stay at zero; otherwise it ships. Rejected: building all cards from docs alone (the registry source is upstream-maintained and the tokens alias cleanly).
- **D5 — `table` is generalized, not installed as-is.** The installed data table hardcodes Model/Context/Cost columns over a `ModelUsage[]` type. We keep its styling language but adapt the component to the fence shape `{columns: [{key, label}], rows: [object]}`.
- **D6 — Fence bodies carry semantic data only.** Presentational/derived props the catalog elements require (`visibleCount`, `cycle`, `onCancel`, React nodes) are derived by the adapter or dropped — never asked of the model. `mermaid`/`diagram` bodies are raw diagram source (not JSON); `diagram` renders inside the catalog's zoom chrome. `math` steps carry LaTeX strings the adapter renders via the existing KaTeX lane.
- **D7 — Rich-cards doc rides the L1 base prompt.** The fence conventions (one line per tag, "cards only when a visual beats prose") become a section of the embedded `promptdocs/AGENTS.md` template. Alternatives rejected: per-agent `AGENTS.md` seeding (write-once — never reaches existing agents; the bug this change fixes); skills (progressive disclosure — the body loads only on a `skill` tool invoke, so the convention is absent at generation time); a standalone composer virtual doc (equivalent behavior, but with D8 in place the L1 template is the natural single home for platform boilerplate).
- **D8 — L1 base prompt is injected per build, never materialized.** `Compose` and `trimmedUnattendedDocs` use `promptdocs.BasePrompt` directly; `SeedWorkspace` stops writing `AGENTS.md`; a startup sweep (alongside the existing system-skills sync at server start) deletes `AGENTS.md` files seeded into existing workspaces — the injected prompt supersedes them, and a leftover file would show the agent stale content at `/workspace/AGENTS.md` through the jailed mount. IDENTITY/SOUL/BOOTSTRAP/HEARTBEAT remain workspace files (LLM regeneration with backups; birth sequence). Tool-side references to a seeded `AGENTS.md` are updated with the sweep.
- **D9 — Heavy engines are lazy with degraded first paint.** `mermaid` and the shiki highlighter load via dynamic import on first need (the KaTeX pattern); until loaded, code renders plain and diagrams render raw source, upgrading in place. While a fence streams, highlighting is skipped (plain) — the highlighter's built-in streaming defer/delay covers the close transition.
- **D10 — Sequencing.** `adopt-assistant-ui-elements` (complete, unarchived) archives first; its workspace-tools delta then lands, and this change's MODIFIED "Tool catalog" requirement replaces it — the removed trio exists only transiently in the main spec. This change's `web-app/generative-ui` requirements are ADDED with names distinct from adopt's element requirements, which remain true as legacy-envelope rendering (kept by D3).

## Risks / Trade-offs

- **No model-facing validation loop**: a malformed fence degrades silently (code block); the model never learns. Mitigation: the prompt doc carries exact shapes; degradation is benign (readable source, never blank).
- **Prompt cost is unconditional**: ~300 tokens of fence conventions on every turn for every agent, including agents that never render cards. Escape hatch if it matters later: a per-agent config gate on the section.
- **Fences cannot stream into cards** the way tool args did (a fence is unparseable until it closes). Accepted: cards pop in complete, with the reveal stagger preserving live feel.
- **Upstream drift**: installed catalog source is owned in-tree after install; restyle edits may complicate future re-installs. Mitigation: keep the token aliasing in CSS (not in component files) so re-installs inherit the contract automatically.
- **Sweep deletes user-visible workspace files**: an operator who hand-placed content in an agent's `AGENTS.md` loses it. Accepted deliberately (the file was never a supported customization surface); the sweep logs what it removes.
- **Bundle size**: mermaid + shiki are large; laziness keeps them out of the initial bundle, at the cost of a first-use loading beat on diagram/code-heavy turns.

## Migration Plan

1. Deploy the combined change; the composer immediately injects L1 + rich-cards per build (no state).
2. Startup sweep deletes stray seeded `AGENTS.md` files from existing agent workspaces (logged); new agents never get one.
3. No database migration; no API contract change; stored allowlists naming the removed tools stay inert (unknown keys are dropped silently at resolve time).

## Open Questions
