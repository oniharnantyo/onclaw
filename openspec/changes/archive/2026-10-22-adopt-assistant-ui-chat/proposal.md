# Proposal

## Why

The chat transcript falls short of the predecessor in ways users hit every turn: GFM tables render as raw pipe text (the parser plugin was never ported with the table styles), the floating tasks/plan card is anchored to the chat column and lands on top of the composer, and a set of transcript surfaces the user expects from a modern agent chat — a live "what is the agent doing" line, a terminal block for shell calls, a chat-sized diff header, a web-search landing animation, a conversation map, mermaid diagrams — are missing or thin. The project context names assistant-ui as the chat stack, yet `@assistant-ui/react` sits in `package.json` with no imports while every surface is hand-ported; `enhance-chat-ux` design D15 deferred that call to the user, who has now made it: adopt assistant-ui directly, runtime included, across every chat element, instead of continuing to re-implement its patterns by hand.

## What Changes

- **Adopt the assistant-ui runtime.** Mount `AssistantRuntimeProvider` over a thin `useExternalStoreRuntime` adapter that derives assistant-ui's message tree from the existing zustand chat store — the store stays the single source of truth (sessions, entries, turn lifecycle, variants, queue, approvals, usage, attachments); the adapter is pure derivation of the same reducer output, so a replayed transcript and a live one stay identical. This reverses `enhance-chat-ux` design D15.
- **Rebuild the transcript on assistant-ui primitives and vendored elements** (`npx assistant-ui add`, sources copied into the tree): `thread`, `markdown-text` (GFM built in) with `shiki-highlighter` and `mermaid-diagram` wired through `componentsByLanguage`, `reasoning`, `day-separator`, `typing-indicator`, `thinking-indicator`, `message-actions`, `message-branches`, `scroll-anchor`, `conversation-map`, plus tool renderers `tool-call`, `tool-fallback`, `tool-group`/`tool-timeline`, `terminal-block`, `code-diff`, `web-search`, and `agent-plan`/`subagent-list`/`task-card` for run surfaces.
- **Rebuild the composer on assistant-ui elements**: `composer`, `composer-slash-commands`, `composer-mentions`, `composer-trigger-popover` (skills and triggers), `model-selector`/`composer-model-picker` (agent, model, effort), `composer-context` (context ring and breakdown), `attachment`/`composer-attachments`, `message-queue`. Existing composer behavior (Enter to send, queueing, stop control, persisted session choices) is preserved.
- **Fix markdown rendering**: tables, task lists, strikethrough and autolinks render as GFM; ordered lists render numbered; fenced `mermaid` blocks render as diagrams once the message completes (source while streaming, source plus a quiet failure note when the diagram does not parse), re-rendered on theme change.
- **Move the run surfaces** (tasks and plan) to float over the transcript viewport's top-right, clear of the conversation map rail, never over the composer.
- **Map the shipped tools onto element renderers**: shell → `terminal-block` with exit status, timeout and truncation derived from the eino execute output markers and the recorded duration; edit → `code-diff` with +/− counts over the existing line diff; web search → `web-search` with query pill, searching shimmer and staggered results; heavy turns → `tool-timeline` trace rows with file-change stats; everything else → `tool-call`/`tool-fallback`.
- **Theming**: vendored sources keep their shadcn token vocabulary; a token alias layer in the theme CSS maps those names (and the elements' shared `surfaces.tsx` surfaces) onto buddies' onclaw-v2 token contract so both themes ride the existing tokens and `npx assistant-ui add -o` re-vendoring stays possible. No per-file edits of vendored components.
- **Dependencies**: bump `@assistant-ui/react` from `~0.15.16` to the registry's current version and pin; keep `@assistant-ui/react-markdown`; add `mermaid` (lazy-loaded), `remark-gfm`, and whatever the registry manifests declare (expected: `motion`, Radix primitives). `react-markdown` is no longer imported directly.
- **Scaffolding**: `components.json` for the assistant-ui registry (Radix style), tsconfig `paths` for the `@/` alias Vite already resolves, lint configuration so `vp check src` tolerates vendored sources.

## Capabilities

### New Capabilities

_None._ The runtime adapter and the vendored component layer are implementation architecture; every user-visible behavior lands in existing chat capabilities.

### Modified Capabilities

- `chat-view`: "Chat transcript rendering" gains GFM markdown (tables, task lists, strikethrough, autolinks, numbered ordered lists) and a turn-activity indicator — a typing indicator before the first token and a live status line naming the running tool with elapsed time; "Code block presentation" gains mermaid fenced blocks rendered as diagrams once complete, source while streaming, graceful failure, theme-aware re-render; "Conversation minimap" becomes the conversation map — one tick per turn, the turn being read marked, on-screen turns deepened, hover preview, click to jump; "Day dividers" gain hover-revealed per-message timestamps.
- `chat-tool-cards`: "Interactive tool bodies" — the shell body becomes a terminal block with exit status, duration, timeout/truncation states, copy control and cursor while running; the edit body carries a filename header with added/removed counts; the web-search body shows the query pill, a searching state, a "read N sources" line and results landing one by one. "Heavy-turn folding" — the expanded fold presents compact trace rows (icon, verb, target chip) with a trailing row of per-file change stats, the last row shimmering while running, each row opening its full card.
- `chat-panels`: "Run card tasks lane" / "Run card plan lane" — the floating run surface anchors to the transcript viewport's top-right, clear of the conversation map, and MUST NOT overlap the composer.

## Impact

- **Frontend view layer** (`frontend/src/features/chat/**`): the transcript, tool-card, indicator, minimap, run-card and composer components are replaced by assistant-ui primitives and vendored elements under `frontend/src/components/assistant-ui/`; a new external-store adapter module sits between the store and the runtime. The zustand store, its reducers, the transport layer and the tool parsing/display helpers (`tools/parse.ts`, `tools/toolDisplay.ts`, `toolPaths.ts`) are retained and reused by the renderers. The ~40 chat test files are rewritten against the new components.
- **Dependencies / tooling**: `@assistant-ui/react` bump (0.x — weekly churn; pin after adoption), `mermaid`, `remark-gfm`, registry-declared packages; `components.json`; tsconfig `paths`; lint tolerance for vendored code. Bundle growth (mermaid, shiki, motion) must stay behind lazy imports.
- **Design contract**: a shadcn→buddies token alias layer joins `tokens.css`/`theme.css`; the daisyUI grep gate stays at zero; a hallmark audit closes the change. `enhance-chat-ux` design D15 is superseded and recorded as such.
- **Backend**: no Go changes and no bindings regeneration — exit status, timeout and truncation are parsed client-side from eino's execute markers; stdout/stderr are one combined stream so no stderr lane is offered.
- **Sequencing**: `enhance-chat-ux`'s delta specs were synced into main before this change (its `chat-tool-cards` spec and `chat-view` requirements are the baseline modified here); `replace-daisyui-with-styled-components` remains active on manual sign-off only and is unaffected.
- **Unknowns to retire first**: the registry's dependency manifests could not be fetched from here, so the first implementation task is a scratch-branch spike running `npx assistant-ui add` for the full element set and recording what it installs; whether `thread-list-sidebar` can express per-agent session grouping decides if the sessions rail is rebuilt or kept.
